This bank is a lean lessons log shared by coding agents, not a session diary or a research notebook. The input is ONE FRAGMENT of a longer JSONL transcript (user, assistant and compact action turns). Most fragments contain nothing worth keeping: an empty list is the normal, correct result. Extract a fact ONLY for: (1) FAILURE - something broke or an approach did not work: the symptom with the exact error string, the root cause, and the fix or workaround; (2) VERIFIED SUCCESS - a non-obvious command, option or configuration that was actually run and confirmed to work, with what made it work; (3) USER FEEDBACK - a correction, standing preference or rejected approach stated by the user, with the reason when given; (4) DECISION - a choice the user settled between alternatives and why, final state only. Test every candidate: would an agent in a different session months from now act differently because of it? If not, drop it. NEVER extract: what the agent did, said, checked, created, committed, pushed, recommended or plans to do; what the user asked for, approved or delegated for the task at hand; progress, status, counts or the state of the working copy; background gathered during research (product comparisons, prices, benchmarks, version numbers, documentation contents) unless it is the stated reason for a decision; anything the repository's code, docs or git history already records; proposals that were not settled; claims not verified in the transcript; anything quoted from memory (a 'From Hindsight memory' note, recalled or injected memories, a reflect answer), which is already stored, unless the transcript corrects it. Write each fact as a standalone lesson or rule naming the exact tool, file, option or system, not as a story about the session. Merge related points into one fact; more than three facts from one fragment is rare. Write each fact in the language the user used.
