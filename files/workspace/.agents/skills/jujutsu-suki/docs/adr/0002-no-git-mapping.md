# 不做 git→jj 命令映射

几乎每份 jj 文档都以 git→jj 对照表开场，本 skill 明确拒绝这个形状。

git 的模型（HEAD + 暂存区）是**游标中心**的：要改一个提交就得先站上去。逐命令翻译教会 agent 的是"游标中心的 jj"——于是提交混杂时它只会 restore 重做（git 里唯一会的招，而 jj 的自动跟踪使它还会静默删除新建文件），意识不到 `absorb` / `squash --from --into` / `split -r` 这些**不移动游标的改动路由**。

映射表还天然遗漏 git 无对应物的动作：`jj split -A/-B` 能把改动抽成新提交放到 DAG 任意位置，任何对照表都不会有这一行，因为左列写不出来。

骨架改为五条 jj 原生能力：DAG 视角（自动重建历史）、稳定 change ID、随意切换 working copy、自动快照、改动路由。

取舍：agent 失去"立刻眼熟"的 git 入口，换来不把 git 的形状带进 jj。
